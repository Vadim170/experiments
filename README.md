# Android-приложения

Два независимых Android-приложения в одном Gradle-проекте.

| Модуль | Приложение | О чём |
|---|---|---|
| [`:app`](app/README.md) | **BLE Scanner** | Постоянно сканирует BLE в фоне, подключается к подключаемым устройствам, читает характеристики, привязывает обнаружения к координатам |
| [`:obdmap`](obdmap/README.md) | **OBD Trip Map** | Подключается по BLE к ELM327, снимает с шины скорость, расход и ускорение, строит карту поездки в реальном времени, хранит историю и разбирает расход по скоростям |

Модули не зависят друг от друга: у каждого свой `applicationId`, свои экраны и
свой набор разрешений. Пара мелких утилит (гаверсинус, логгер) намеренно
продублирована — общий модуль ради полусотни строк усложнил бы сборку сильнее,
чем сэкономил.

## Сборка

Требования: JDK 17+, Android SDK 35, build-tools 35, minSdk 26.

```bash
echo "sdk.dir=/путь/к/android-sdk" > local.properties

./gradlew assembleDebug        # оба APK
./gradlew testDebugUnitTest    # 112 юнит-тестов
./gradlew lintDebug            # MissingPermission поднят до уровня ошибки
```

Готовые debug-сборки лежат в [`artifacts/`](artifacts/):

```bash
adb install -r artifacts/blescanner-debug.apk
adb install -r artifacts/obdtripmap-debug.apk
```

### Локаль сборки

Тесты названы по-русски, и Kotlin складывает имя метода в имя `.class`-файла
для лямбд внутри теста. В окружении без UTF-8 локали (`LANG` не задан, как в
голых CI-контейнерах) компилятор падает с `InvalidPathException`. Лечится
локалью, а не кодом:

```bash
LANG=C.UTF-8 LC_ALL=C.UTF-8 ./gradlew testDebugUnitTest
```

Android Studio на любой из десктопных ОС ставит UTF-8 сама, так что вручную это
нужно только в контейнерах.

## Общие решения

Оба приложения написаны в одном стиле, и грабли у них общие:

* **`WAKE_LOCK` обязателен в манифесте.** Без него `acquire()` кидает
  `SecurityException` и роняет процесс, а `START_STICKY` тут же поднимает
  сервис — приложение падает по кругу.
* **Тип foreground-сервиса собирается в рантайме** из фактически выданных
  разрешений: на Android 14+ `startForeground` с неподкреплённым типом кидает
  `SecurityException`.
* **`Locale.US` во всём форматировании чисел.** Иначе разделитель дробной части
  пляшет вместе с языком системы, и одни и те же цифры в логе, на экране и в
  базе выглядят по-разному, а `geo:`-ссылки с запятой просто не открываются.
* **Чистая логика вынесена из Android-классов** (`Geo`, `DetectionPolicy`,
  `ObdParser`, `FuelMath`, `TripAccumulator`) — она покрыта обычными
  JVM-тестами, без эмулятора.
